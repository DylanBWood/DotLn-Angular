## Findings

- **F1 — blocking, regression of `main` behavior, high.**
  [WO-007-D008](../../evidence/WO-007/decisions.md#wo-007-d008),
  `FUP-e68c57560698ecdb`. `provideDotlnState()` registers
  `DotlnErrorHandler`, whose `handleError(_error)` dispatches a fixed
  `AppError` and does nothing else with the error. Reproduction: build the
  base and the subject for production, serve both on loopback, open
  `/board`, and run `window.dispatchEvent(new ErrorEvent('error', { error:
  new Error('probe-uncaught-error') }))`. Observed on the base:
  `ERROR Error: probe-uncaught-error at …` in the console. Observed on the
  subject: nothing in the console, and a toast reading
  `A request failed (unknown).`. A fixture spec in a scratch copy shows the
  same at unit level: Angular's default handler reports the error, the
  provided one does not, and `ErrorStore.latest()` holds only
  `An unexpected application error occurred.`. So the message and stack of
  an uncaught error reach no surface at all, in development, in the
  `mocked` build or in production. Rule a repair must hold: the application
  `ErrorHandler` reports each error it receives to the console with the
  original error value, as Angular's default handler does, and still
  dispatches `errorEvents.unhandled`; a spec under `libs/shared/state`
  asserts both.
- **F2 — follow-up, test coverage, medium.**
  [WO-007-D009](../../evidence/WO-007/decisions.md#wo-007-d009),
  `FUP-f7b74cdf0c6278bf`. Reproduction: in a scratch copy of the subject, set
  `libs/shared/data-access/src/test-setup.ts` to `onUnhandledFrame: 'bypass'`,
  then to `listen({})`, and run the spec named
  `fails an unhandled request instead of contacting a real service`. It
  passes both times, with ECONNREFUSED standing in for MSW's refusal.
  Expected: the spec fails without the strategy it stands for. Rule a repair
  must hold: the spec fails when the Node setup's strategy is `bypass` or
  absent (for example, a live in-test server answers the unmatched address,
  or the spec asserts MSW's unhandled-frame error), and the two documents
  describe what the test proves.
- **F3 — follow-up, operator flow, low.**
  [WO-007-D010](../../evidence/WO-007/decisions.md#wo-007-d010),
  `FUP-771de887c34450f7`. `ShellNotices` renders every error with
  `shell.requestFailed`, so an uncaught application error reads as a request
  failure (observed in the F1 probe). `main` had no notice. Rule a repair
  must hold: the notice names a request failure only for an HTTP failure.
- **F4 — follow-up, evidence, low.**
  [WO-007-D011](../../evidence/WO-007/decisions.md#wo-007-d011),
  `FUP-a8081dab218b7415`. Execution step 12 directs the decisions file to
  record the kit file at starter v0.94.0 with the schema's SHA-256. The
  README records it, and D001 to D007 do not. The fact holds (digest
  `7d20e785…` for the kit file, the moved copy and the base's copy). Rule a
  repair must hold: the decisions file carries that record.
