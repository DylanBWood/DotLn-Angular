**Design:**

- **Types** (`libs/shared/models/src/lib/toolbox.ts`): `Tool` gains
  `definition: string`; `place: { part?: string; chapter?: string;
  section?: string; subsection?: string }`; `related: readonly { title:
  string; id: ToolId | null }[]` (resolved at join time within the same
  work by exact concept title; an unresolved relation keeps its title with
  `null`); `hooks: readonly { domain: HookDomain; clause: string }[]`, with
  `HookDomain` the maps README's eleven codes (`D1` planning to `D11` agent
  behaviour) as a labelled enum; `verified: { kind: 'sourced' |
  'model-knowledge' | 'partial'; note: string }`, derived from the row's
  `verified` field (a value starting with `model-knowledge` or `MK` is
  `model-knowledge`, a value naming a source is `sourced`, the run's one
  partial row is `partial`). The schema becomes `tool-v1.schema.json` with
  `additionalProperties: false` over the full field set and no length limit
  on `title`, `definition`, a clause or a reason; the checkpoint shape and
  `catalog-summary.json` bump to `v1`, and the summary gains, per work, the
  chapter list with its concept counts and the scene tools (below). A reader
  of `tool-v0` data is kept in the loader for one release and removed by the
  order that next touches the loader (operating rule I3).
- **The join** (`tools/scripts/catalog/join-maps.mjs <maps root>`, `npm run
  catalog:join`): for each tool of the eight data files, reads its row by
  `map.file` and `map.line` under the run's folder on this machine (core's
  ignored intake, read-only), checks each file's SHA-256 against the digest
  the data file recorded (a changed digest stops the join and is a decision,
  never a silent renumbering), writes `definition`, `place`, `related`,
  `hooks` and `verified` into the tool, resolves `related` within the work,
  and rewrites the eight data files and the summary in place. The executor
  runs it once and records the eleven digests read in the decisions file.
  The run's quarantine files are not inputs and are never opened: they were
  quarantined for employer material, which is the clean room's own floor.
- **The check** (`check-catalog.mjs`): Ajv against `tool-v1`; ids unique;
  the count of `provenance: 'map'` rows equals the summary's mapped rows;
  every typed row's kind in `TransformKind`; every untyped row's reason
  non-empty; every `related.id` that is not `null` names an existing tool;
  every row's `definition` non-empty and `place.chapter` present. The
  `assertScrubbed` call over catalog strings, the refused-field list, the
  title and clause length limits and the `with-definition.json` negative
  fixture go: they enforced a rule nobody gave (WS-001 rule 23 as corrected).
  The hidden-file rule of WO-014-D028 stays. The reducer's scrub over the
  platform's control records (WO-016) is untouched, because an account name
  or a hostname in a record is the clean room's floor.
- **Typing for the scene:** the executor types, by decision in the decisions
  file with the row's definition as the warrant, the rows the scene's rail
  floor needs: Arrive (`aifg-a:112`) as a `steer.blend` term with slow and
  target radii; Seek (the §3.3 row the join finds by title), Separation
  (`aifg-a:131`), Velocity matching (`aifg-a:118`) and Wander (`aifg-a:125`,
  with Random binomial `aifg-a:104` as its parameter) as `steer.blend`
  terms; Slot assignment (`aifg-a:186`) as the `formation.twoLevel`
  parameter set that carries the cost table by role; the formation-pattern
  rows (wedge, line and column, or the single pattern row part A carries)
  as `formation.twoLevel` patterns; an `objective.set` tool on the row that
  describes a target position (Seek's target or the "Target" row; where no
  row fits, the objective stays the scene's own action and the decision says
  so); `squad.form` and `squad.dissolve` on the rows that describe group or
  squad membership where part A names them. The summary's `firstThree`
  becomes `sceneTools` per work: the typed tools whose kind the scene engine
  interprets. The shortfall WO-014 recorded for Team Topologies is kept as
  it was; the quota rule is gone with the pipeline that needed it.
- **The reading surface** (`libs/features/tools`): `catalog-page`
  (container) over `ToolsFacade`; `catalog-layout` (slots `[search]`,
  `[shelf]`, `[contents]`, `[reading]`, `[history]`; fluid, no fixed width);
  composites `work-shelf` (the six works with title, count and scene type,
  the chosen one marked, each title in its work's colour), `contents-list`
  (the chosen work's chapters with counts, the chosen chapter's sections,
  the chosen section's concepts; one keyboard path through the three
  levels), `concept-reading` (the title at the page's largest size, the
  type and the place as a small line, the definition in a 65ch to 70ch
  measure, the model-knowledge mark when the row is the worker's reading,
  the relations as links in running text, the hooks as sentences under one
  heading naming the domain, the faces as one sentence with the parameters
  and their defaults when the tool is typed, the untyped reason as a
  sentence when it is not, and the line "runs in the soldier scene" with a
  link to `/scene?tool=<id>` when the kind is one the scene interprets and
  `BasePaths.Scene` resolves to a page that is not the arriving page),
  `catalog-search` (one text field over title and definition, client-side,
  results as concept rows with work and chapter, Enter opens the first;
  work, kind and status as facets inside the results, never the page's
  first form), `reading-history` (the last ten readings as links); mappers
  `reading-mapper` (a `Tool` to the reading view model, the faces sentence
  through translation templates with the values as data), `hook-domain
  -mapper`. The `tool-list` and `tool-faces` composites and the filter row
  are removed. `CatalogStore` persists the chosen work, chapter and concept
  and the reading history through WO-007's `withPersistedState` under
  `dotln-angular.tools`, ignoring a stored value of WO-014's shape.
  `catalogPageEvents` gains `workChosen`, `chapterChosen`, `conceptOpened`,
  `relationFollowed`, `searched`; `filtersChanged` and `pageChanged` stay
  for the facets. The Tools home names the catalog by what it is: the
  works, their counts and the last reading.
- **Design brief** (WS-001 rule 25): the page reads like a well-set

  tool's provenance; the search as one field at the top; no card grid, no
  label-value list, no fixed page width, nothing animated at rest. Two
