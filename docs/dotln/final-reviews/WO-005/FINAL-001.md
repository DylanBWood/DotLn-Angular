## Implementation review

The change applies the Design with one recorded departure, D001's split of i18n: reusable translation behavior in shared i18n with its own `I18nConfig` and `provideI18n()`, the application adapter in core, and one new edge, core to i18n, in the boundary rule and the conventions table. That is the right shape: it keeps i18n reusable by another application and avoids the i18n-to-core import the Design's text implied, which house rule 15 forbids. WS-001's rule 15 still lacks the edge (VER-001 F7, planning).

`provideDotlnCore()` composes zoneless change detection, the browser error listeners, fetch HTTP, the router with input binding, the environment token and the base path through `makeEnvironmentProviders`; `app.config.ts` adds `provideDotlnI18n()`. The empty route redirects to `BasePaths.Home` and the home component loads lazily, so `/` lands on `/home`; the app spec asserts the URL. `buildRoute()` keeps path commands apart from query parameters and copies the query object. The base path is read from `<base href>` with `/` as the default, and the one `providedIn: 'root'` factory is `AppBasePathToken`'s, which core also provides explicitly (D005, awaiting the operator's ruling).

The utility adapters repair two upstream declarations without touching runtime: `filter` returns a variable-length array and makes dictionary keys optional, with placeholder, map, dispatch and transducer overloads; `isNonEmptyString` narrows primitives to a branded string and leaves `unknown` unnarrowed because a placeholder is truthy. Each repeats one overload at the end of its interface so `R.pipe` infers from it, and the comment says so. The ported specs pin the house export to the upstream function object. VER-001 F2 stands: the namespaces carry nearly all of both libraries into the production bundle, which house rule 1 ranks above house preference; the Design prescribes the namespace form, so the planning route decides (D009).

The i18n loader refuses an unconfigured language and encodes the identifier; the missing-key handler throws in development and returns the key in production; `TPipe` extends `TranslocoPipe` as an impure pipe named `t`. The kits return `providers` plus handles, and the kit check resolves `const` aliases through TypeScript symbols within lexical scope, which closes the forged-kit path the executor's reviewer found (D007). The primer validates every `DOTLN_` key, refuses credentials in URLs, keeps values out of diagnostics and writes its outputs with mode 0600 under ignored paths. The `tools` project's uncached `lint` target carries the checks into the registered gate, and CI also runs them explicitly.

What a maintainer may not understand in six months: the `basePath`-less `prefer-readonly` block in the root ESLint configuration, which never reaches a project's files (VER-001 F1, D008); the discovery rule of the template check, which D017 and the comment in `templates.mjs` now state; and the three generated `eslint.config.mjs` files, which spread the root configuration after the Angular flat presets. Nothing simpler holds the same contract for the adapters, the primer or the checks. The repairs in this review are described in D017 to D019.
